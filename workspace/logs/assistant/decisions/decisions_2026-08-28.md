# 决策日志 — 2026-08-28

## D-001 需求范围：截图类图片优先

- **背景**：用户目标是"打开图片改文字"，输入类型未指明
- **决策**：锁定 A 类（网页/App 界面/聊天记录截图）为 v1 主场景；照片透视文字（C 类）明确排除
- **理由**：截图 = 系统字体渲染，本地可精确匹配；照片文字需透视矫正，技术复杂度翻倍，v1 不做
- **影响**：字体候选集收敛、全离线可行

## D-002 精度目标：C 档（完全看不出修改痕迹）

- **背景**："保证字体一致"存在三档精度
- **决策**：采用最高档——字体+字号+颜色+字间距+效果全还原
- **理由**：用户明确选择；截图场景下此档可行
- **影响**：必须"抹除+重绘"全流水线，验收用 SSIM 量化

## D-003 交互形态：自动识别 + 手动兜底（A+B）

- **决策**：OCR 自动框选为主线，手动框选/修正/删并/合并为兜底
- **理由**：OCR 不可能 100% 准确，必须给用户接管权，避免用户体验卡死在识别失败上
- **影响**：交互复杂度可控，兜底线覆盖全部 OCR 失败模式

## D-004 技术栈：Swift 原生（macOS）

- **决策**：Swift + SwiftUI 原生应用，产物为标准 .app
- **理由**：OCR（Vision）、字体匹配（CoreText 渲染比对）、字体库（系统）全链路用苹果能力，链路最短、体验最顺
- **否决**：Python（打包体验差、字体匹配自造轮子）、Electron/Tauri（OCR 字体能力桥接层多、体积大）
- **影响**：无跨平台诉求，合理

## D-005 字体匹配路线：像素级渲染比对为主、视觉参数近似兜底

- **决策**：候选字体渲染同文本 vs 原图文字做结构相似度比对；失败时用视觉特征挑最近似系统字体 + 明确标注"近似匹配"
- **否决**：AI 深度学习字体识别（对系统字体为主的截图是杀鸡用牛刀，模型重、开发量大）
- **影响**：全离线、可解释、毫秒级；非系统字体场景有诚实提示

## D-006 v1 边界：纯色文字精确处理，复杂效果披露不硬扛

- **决策**：渐变/描边/霓虹等复杂文字效果 v1 仅"尽力逼近"并 UI 披露；复杂背景抹除残影列为已知风险
- **理由**：YAGNI + 完成优先；80%+ 截图是纯色文字
- **影响**：验收标准分合成样本（严格线）与真实样本（人工判定），不混为一谈

## D-007 字号显示单位：内部 px，UI 显示 px + 2x 折算 pt 参考

- **来源**：zhanshen 待裁决项 A（PRD 未定义字号单位）
- **裁决**：采纳架构假设。渲染/内部一律 px（截图是像素世界，无换算误差）；UI 展示 px 并附 2x 折算 pt 参考，兼顾 Retina 直觉
- **依据**：源码图即像素，pt 仅是人机参考

## D-008 最小字号下限：相对下限 + 绝对下限取大者

- **来源**：zhanshen 待裁决项 B（"最小字号"未定义）
- **裁决**：v1 定义 `F_final ≥ max(0.5 × 原字号, 8px)`。相对下限保排版感知，绝对下限保可读性，两者取 max
- **影响**：写入参数表 k_min 语义（0.5 相对 + 8px 绝对）

## D-009 撤销/重做范围：含全部文档变更

- **来源**：zhanshen 待裁决项 C
- **裁决**：撤销/重做覆盖内容修改 + 几何操作（移动/缩放/增删块）+ 字体/样式调整；仅"预览确认"动作入栈
- **理由**：拖框改错位置而无法撤销不可接受；预览确认是明确动作，入栈符合用户心智
- **影响**：Undo 采用 Command 模式（物化块级裁剪增量），xiaoyou 状态层按此实现

## D-010 近似匹配展示口径：字体 + 字重同显

- **来源**：zhanshen 待裁决项 D
- **裁决**：采纳默认——近似匹配时显示"字体 + 字重"（如"苹方 中黑 近似"），供用户手动下拉精修
- **理由**：近似匹配场景信息越足越有利用户纠偏

## D-011 空文本语义：支持"只抹除不重绘"（erase-only）

- **来源**：zhenhai 待裁决项 2（`.emptyText` 阻断渲染）
- **裁决**：v1 支持空文本 = 抹除原文 + 不渲染新文字。截图场景"删掉某句话"是真实需求，TextEraser 已独立，成本低
- **影响**：WorkflowError.emptyText 语义变更为"仅当块无任何操作时"; UI 检查器允许清空文本触发 erase-only

## D-012 导出签名：采纳 export(format:to:)

- **来源**：zhenhai 待裁决项 1（tech_spec 签名无 URL 参数）
- **裁决**：采纳实现签名 `export(format:to: URL)`。导出必然需要目标路径，架构签名属疏漏，实现合理
- **影响**：tech_spec §4 以实现为准回填

## D-013 patchRect 边距近似：接受 +1px 边距

- **来源**：zhenhai 待裁决项 3（renderer pad=4px 与 patch 边距 +1px 不一致）
- **裁决**：接受实现近似（tolerance ±2% 披露）。极端情况新字形最外侧 1-3px 可能裁出 patch，属可接受精度
- **影响**：验收时该场景归入"已知精度范围"

## D-014 PRD 验收口径修订：SSIM 对比对象 = 同背景 + 新文本 ground-truth

- **来源**：shouye QA 对抗式审查发现（PRD §6.2 自证陷阱）
- **问题**：原"改字后与原图区域一致性 SSIM ≥ 0.95"字面在内容变更时物理不可达（实测 0.01~0.14）——改了字必然与"改前原图"不同，该指标是伪标准
- **裁决**：SSIM 对比对象改为「同背景 + 新文本 ground-truth」（新文字渲染在无字背景上的正确结果）。这才是"无痕"的真实含义：抹除残留 + 渲染偏差 vs 完美结果
- **影响**：PRD §6.2 已修订；QA E2E 已按新口径验证通过（平坦 0.953-0.987、erase-only 1.000）
