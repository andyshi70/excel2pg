# 需求诊断报告 2026-09-01（追加：多块编辑 D-038）

## 背景
CEO 实测 alpha.5 发现：图片上改了两处数字，每次都只有一处生效；
"我只要点第 2 处，第一处改的部分就还原了"。

## 第一性原理拆解

产品语义 = **P 图换字是持久操作**：用户对每个文字块做的修改应当**落地生效**，
而不是"临时的预览幻影"。多块连续编辑 = 多个独立的持久修改，逐块确认生效。

## 根因（代码证据链，系统调试 Phase 1 完成）

现象：改 A → 点 B → A 还原 → 确认 B → 只有 B 生效

| 环节 | 代码 | 病理 |
|---|---|---|
| ① 点 B `select(B)` | EditorState.swift:128-133 | 只清 UI 草稿/预览叠加，**不物化 A** |
| ② `document.select(B)` | EditorDocument.swift:33-39 | `phase = .selected(B)` **覆盖 A 的 `.preview(A)`**——A 预览态被静默吊销 = "还原" |
| ③ A 的 `pendingEdit` 残留 | EditingWorkflow.swift | 单槽 `PendingEdit?`，B 的 `previewEdit` 覆盖 A |
| ④ 确认 B | EditingWorkflow.swift:253 | 只认 `pendingEdit.blockID == B` → 只有 B 物化 |

**一句话**：编辑是"预览→确认"两步，但切块时 `select()` 既不确认也不撤销前一块，
直接静默丢弃。A 从未入 undo 栈 → 无法找回。

## 修复方案（CEO 已批准方案 A）

**切块/完成输入时自动物化前一块（auto-confirm）**：
- 改 A → 预览 A（可反复调整）
- 点 B → **自动物化 A**（patch 回贴 + 入 undo 栈）
- 改几处生效几处；undo 逐步回退

**阻塞处理（方案 A）**：
- 前一块预览被阻塞（collision/tooLong/样式未就绪）或预览未完成 → **拒绝切块 + 明确提示**
- 不静默丢用户输入

## 边界场景（PRD 输入）

| 场景 | 行为 |
|---|---|
| A 预览合法（无阻塞） | 点 B → auto-confirm A → 切到 B |
| A 被碰撞阻塞 | 点 B → 拒绝切换，提示"与相邻文字块重叠" |
| A 超长 | 点 B → 拒绝切换，提示"文字过长" |
| A 预览未完成（in-flight） | 点 B → 拒绝切换，提示"预览尚未完成" |
| undo | 每块物化独立入栈，逐步回退 |

## 验收标准（QA）

1. 两处连续编辑 → 两处都生效（源图双块均改）
2. 阻塞场景切块 → 拒绝 + 提示文案正确
3. undo 逐块回退（先 B 后 A）
