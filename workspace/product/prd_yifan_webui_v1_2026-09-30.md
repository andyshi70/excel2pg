# PRD：yifan 可视化 WebUI v1（小白免 SQL 数据工具）

- 日期：2026-09-30
- 版本：v1（grilling 共识稿，经用户逐轮确认）
- 数据库：PostgreSQL `yifan`（localhost:5432，凭据 `/Users/evandy/excel2pg/.env`）
- 技术栈：Streamlit + psycopg2 + openpyxl（与 excel2pg 同语言同 venv）

---

## 一、总目标

用 PostgreSQL + 可视化 WebUI 替代 Excel 复杂公式（VLOOKUP、多表匹配、计数）。
用户 = 完全不懂 SQL 的小白。界面**只能点选**，全程不出现 SQL、Join、主键、公式。

**非目标（明确砍掉）**
- 分组汇总/数据透视（后续可能加，v1 不做）
- 查询结果回写（查询 = 只读 + 下载；只有三种计算能写回）
- 正则、跨列比较、公式表达式
- 多人部署/登录（单机 localhost）
- 导入功能（excel2pg 导入器已支持选表更新，不在本项目范围）

## 四、四种操作的向导状态机

公共约定：所有向导状态存 `st.session_state`；配置（表选择、键配对、状态过滤）持久化到本地 JSON，启动预填。

### ④ 数出现次数（COUNT → integer）
```
选主表 A（多选：硕士/直博）
 → 选数数用的对照表（默认 总0924）
 → 配对键：左栏勾 A 的列、右栏勾对照表的列，按顺序一一对应
   （两栏多选，界面呈现为 ←→ 配对行；不写死任何字段名）
 → 「要数哪些人？」多选，默认{录取, 专项录取}，大白话标签
    （只数正式录取的 / 把候补也算上 / 全都数）
 → 「结果写到哪一列？」下拉已有列（预填对的）| +新建一列（输中文名，自动建 integer）
 → 可选筛选（多选值，按具体值；不填跳过）【只影响右侧显示与下载，不进写回】
 → 人话确认页 → 执行 → 右栏结果
```

### ③ 判断在不在（EXISTS → '是'/'否'）
同 ④ 的骨架，差异：
- 对照表默认 `二轮推免开放目录`
- 无「数哪些人」一步
- 写入列类型自动 text（已有列类型不符则 ALTER）

### ② Vlookup（补一列，2026-09-30 定名 Vlookup）
同 ③ 骨架，差异：
- 多一步「**带出对照表的哪一列？**」→ 勾选 B 表中一列（带出其列名作为新列名，用户可改）
- 找不到 → 填空（可选默认值如"无"）
- B 匹配到多行 → 取第一行 + 右栏黄条「B表里有 N 行都对上了，只取第一行」
- 新列类型跟随 B 源列

### ① 查数据（只读）
```
选主表 A → 要不要连另一张表？(否/是)
 是 → 选对照表 → 配对键（同上）→ 连接方式（三张单选卡片，带实时预估行数）
      ·「A表全保留，B表对得上的带过来，对不上的留空」（左连）
      ·「只要两边都能对上的」（内连）
      ·「只要B表里有的，把A表信息贴上去」（右连）
      重名列自动加表名前缀（硕士_医院 / 总0924_医院）
 → 加筛选条件（多行：[字段▾][说法▾][值]，说法=等于/不等于/包含/大于/小于/在…之中/是空的/介于，
    条件间 并且/或 切换；默认全部并且）
 → 结果表 + 下载 xlsx
【本操作无确认执行按钮 — 不回写数据库】
```

## 五、匹配内核与写回 SQL 规则

**核心洞察：两个计算的值都是「该行自身键字段」的纯函数 → 不需要主键，单条 UPDATE 完成。**

### 匹配规则
1. 键配对完全由用户勾选决定，**代码零硬编码字段名**；SQL 生成时取勾选列表逐列 `AND 等值`
2. 归一化（强制开）：`btrim(去首尾空格)` + `全角括号（）→半角()`，两边同时施加
3. 导师名末尾数字归一：**默认关**，向导里可选开关（实测能救 53 行失配，但可能误伤，属口径变更）
4. 判断在不在 = `EXISTS`；数次数 = `COUNT(*)` + 状态过滤；vlookup = 相关子查询取 LIMIT 1

### 写回规则
```sql
BEGIN;
CREATE TABLE 硕士_bak_YYYYMMDD_HHMMSS AS TABLE 硕士;   -- 备份，回滚=恢复它
-- 目标列类型不符时先 ALTER（如 硕士.推免目录开放情况 integer→text）
UPDATE 硕士 a
SET 推免已招 = (SELECT count(*) FROM 总0924 c WHERE <配对键等值+归一> AND c.是否录取 IN (...)),
    推免目录开放情况 = CASE WHEN EXISTS (SELECT 1 FROM 二轮推免开放目录 b WHERE <配对键等值+归一>)
                       THEN '是' ELSE '否' END
WHERE a.学位类型 IS NOT NULL;   -- 守卫：垃圾总计行整行不碰（守卫列=用户勾的第一键列）
COMMIT;   -- 任一步失败 → ROLLBACK，原表零改动
```

**保障清单**：
- 单事务，先备份后更新，失败全回滚
- 重跑幂等（值=行的纯函数，覆盖写入）
- 筛选只作用于右侧显示/下载，**永不进 UPDATE**（避免"部分行有值部分行永远空"的数据不一致）
- 不加主键、不换表、不加索引、不碰其他列
- 三张计算卡片共用**同一套引擎**；用户原有两个固定计算 = 该引擎的预填配置，500/500、200/200 即回归测试

### 重导入联动
每次启动/刷新时查 `information_schema`：目标列缺失 → 右栏黄条「表已重新导入，之前算的结果没了，一键重算」（约 20 行探测代码）。

### 错误映射表（约 8 条，技术原因 → 小白话 + 下一步）
| 技术原因 | 界面文案 |

## [第一性原理分析]

**本质拆解**：用户的问题不是"做一个 BI 工具"，是"Excel 辅助列 + VLOOKUP + COUNTIF 这套手工流程的固化"。拆到不可再分：
1. 数据已结构化落库（excel2pg 完成）→ 剩余缺口只是**把三张表的键对齐逻辑从用户脑子里搬到工具里**
2. 两类计算（EXISTS / COUNT）都是**行级纯函数** → 这决定了写回必然是一条 UPDATE、必然不需要主键 —— 不是选型偏好，是问题结构决定的
3. 小白约束的本质是**禁止暴露中间表示**（SQL/公式）→ 所有中间产物必须翻译成人话，包括确认页和报错

**由本质推出的架构**：引擎（可数值验证）与壳（Streamlit 向导）分离，先引擎后壳 —— 因为引擎的正确性有 500/500 的客观裁判，壳没有；先做壳会把错误藏进不可验证的 UI 里（用户历史 demo 翻车的结构性原因）。

## [对抗审查记录]

**如果…会怎样（3 个边界）**：
1. **如果重导入后键列语义变了**（如"学位类型"词表新增"直博生"）→ 命中率静默暴跌，小白看到的是一堆"否"/0 而非报错 → 缓解：确认页显示"0 命中共 N 行"统计 + §二 覆盖缺口提示；仍无法自动识别词表变化 → 已在错误映射表注明排查路径
2. **如果执行中 Streamlit 进程被杀** → 单事务保证 ROLLBACK，原表完好；但备份表已建成会残留 → 残留备份无害（只占空间），v1 接受，不做自动清理（YAGNI）
3. **如果用户勾错键配对**（专业码↔研究方向）→ 结果必然大面积 0，但工具无法判断"这是错的" → 依赖确认页人话摘要让用户自己看出配对，以及 0 命中统计放大异常

**最可能被推翻的假设**：「配置预填能让小白 5 秒跑完」—— 若用户改动了表结构或换场景，预填反而是误导（带着旧配置一路下一步写错列）。失效降级：预填值在确认页**高亮显示为可点改的摘要行**，且每次执行的确认页必列完整配置（表名、键配对、过滤条件、目标列），确保"预填"永远不等于"不可见"。

**外部依赖失效回退**：PostgreSQL 未启动 → §六 连接失败人话提示（非崩溃栈）；excel2pg 后续 drop-recreate 覆盖计算列 → §五 重导入探测黄条 + 一键重算。

**数据隐私**：真实行数据仅经本地 psql 读取；进模型上下文的只允许统计量（B 模式已确认）；`.env` 密码已出现在早前会话记录，建议用户更换。
