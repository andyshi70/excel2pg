## 1. 背景与定位

用户需要修改截图（网页/App 界面/聊天记录）上的文字，且修改后**看不出痕迹**——新文字与图片上原有文字在字体、字号、颜色、字间距、排版上完全一致。产品为 macOS 原生单窗口应用。

**定位**：原位无痕改字工具。不是"在图上加字"，而是"把图上的字换掉且不被发现"。

## 2. 用户场景（主要 + 典型）

- **主场景**：拿到一张聊天记录截图，想把某个名字/数字/句子改成别的，交付后看不出改过
- **典型场景**：改网页截图上的价格/文案、改 App 界面截图上的文字、用改图做演示/交付物

## 3. 功能需求

### FR-1 图片打开与显示
- 支持 PNG / JPEG / HEIC 格式
- 打开后原分辨率显示（可缩放/平移查看）
- 入口：主页拖拽 / 打开文件对话框

### FR-2 自动文字块检测（OCR）
- 打开图片后自动执行 Vision OCR，检测所有文字块
- 每个文字块输出：文本内容、边框矩形、置信度
- 置信度低的块在 UI 上弱化标记，引导用户人工确认
- OCR 未检到任何文字时进入"无文字状态"，引导手动框选

### FR-3 文字块手动接管（兜底）
- 已检出的文字块：可拖动位置、拖拽缩放边框
- 手动"添加文字块"：用户拖框圈选新区域，对该区域重新 OCR 或直接作为编辑块

### FR-4 样式分析（核心）
对每个文字块自动提取：
- **字体**：用系统已装字体逐个体渲染识别出的文本内容，与原图文字做像素结构比对（SSIM 类指标），最高相似度者胜出
  - 相似度 ≥ 阈值 → 精确匹配（显示字体名与字重）
  - 相似度 < 阈值 → 视觉参数近似（衬线/字重/字宽特征挑最近似字体），UI 标注"近似匹配"，可手动改字体
- **字号**：从文字块像素高度 + 行数估算
- **颜色**：采样笔画像素前景色，剥离抗锯齿边缘干扰
- **字间距**：分析原文字宽/字距，供重绘宽度适配

### FR-5 文字编辑
- 点击文字块进入编辑态，检查器面板显示：文字内容（可编辑）、字体识别结果（可手动改）、字号、颜色、间距
- 编辑内容实时预览重绘效果

### FR-6 抹除与重绘
- **抹除**：inpaint 算法用周围背景像素补回原文字区域（无字时的背景）
- **重绘**：用分析出的字体/字号/颜色在原位绘制新文字，按原文字块宽度自动缩放，不破排版
- 修改结果可撤销/重做

### FR-7 导出
- 导出 PNG / JPEG，原分辨率无损
- 导出成功提示 + 文件路径

## 4. 非功能需求

- **NFR-1 性能**：打开图片 + OCR ≤ 3s（常见截图尺寸）；字体比对单块 ≤ 300ms；抹除/重绘异步执行不阻塞 UI
- **NFR-2 离线**：全流程离线可用，不依赖网络（无商业字体则近似匹配，不联网下载）
- **NFR-3 一致性**：截图场景系统字体集内，字体匹配正确率 ≥ 90%（验收标准，见 §6）
- **NFR-4 可靠性**：所有失败路径有明确 UI 反馈，不静默失败

## 5. 已知限制（明确披露，不假装能做）

| 限制 | v1 策略 |
|------|--------|
| 渐变/描边/霓虹等复杂文字效果 | 仅精确处理纯色文字，复杂效果 UI 提示"已尽力逼近" |
| 毛玻璃/密集纹理背景 | 抹除可能有残影，列为已知风险 |
| 网页内嵌商业字体 | 近似匹配 + 明确提示 + 手动换字体 |
| 极端长度替换 | 自动缩放至最小字号仍超限 → 提示扩大文字块 |

## 6. 验收标准（v1 发布门禁）

1. 打开真实截图 → 自动框选文字块，覆盖 ≥ 90%（样本集内，人工对照）
2. 改字后区域保真一致性：**同背景 + 新文本 ground-truth** SSIM ≥ 0.95（合成截图样本；口径见 D-014——SSIM 对比对象为新文本渲染在无字背景上的 ground truth，非改前原图；原"与原图一致性"措辞物理不可达，已修订）
3. 系统字体集内字体识别正确率 ≥ 90%（单元测试）
4. 全流程离线可用
5. 导出文件分辨率与原件一致
6. 核心链路无崩溃（打开→改字→导出 100 次冒烟）

## 7. 版本规划

- **v1.0（本次）**：全流水线 MVP + 纯色文字精确处理
- **v1.1+（候选）**：描边/阴影检测、批量连续改字、撤销历史增强、HEIC 直存

## [第一性原理分析]

- 事实层：位图文字无文本层，"无痕" = 背景连续 + 文字样式连续；样式的全部可调维度：字体/字号/颜色/字间距/效果/基线；OCR 给内容与位置；抹除 = 像素推断；字体识别 = 渲染比对（确定性计算）。
- 从事实推导：必须"抹除→重绘"而非覆盖；必须逐块提取样式参数；字体匹配必须用渲染比对而非直觉推测；宽度适配保证排版不破。
- 反推验收：既然目标是"看不出来"，验收就该用像素一致性（SSIM）量化，而非人工目测——把"感觉像"变成"测得出"。

## [对抗审查记录]

- **如果 OCR 把一句话拆成两个块？** → 邻近块合并策略（bbox 相邻 + 同行），UI 允许手动合并/拆分
- **如果用户改字后重绘把相邻文字盖住？** → 重绘区域与相邻文字块做碰撞检查，超界提示
- **如果比对的字体在视觉上高度相似（如苹方 vs 冬青黑体）？** → 相似度接近时采用"渲染更接近者"而非"名气更大者"，并保留手动选择入口
- **最可能被挑战**：SSIM ≥ 0.95 的达标线——合成截图可控可达成，真实截图因背景复杂可能不达标；故验收样本分两级：合成样本（严格线）+ 真实样本（人工判定），不混为一谈
