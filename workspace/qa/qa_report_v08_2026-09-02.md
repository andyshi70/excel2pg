## 2. 代码攻击者审查（逐项核对）

### 2.1 白名单 catalog 动态校验 ✅

```swift
// StyleAnalyzer.swift:75-76
let catalogPSNames = Set(catalog.faces.map { $0.postScriptName })
let available = Self.digitFriendlyWhitelist.filter { catalogPSNames.contains($0.postScriptName) }
```

**判定**: 白名单面必须在 catalog 中存在才可选。catalog 来自 `FontCatalogBuilder.buildDefault()`（`CTFontManagerCopyAvailablePostScriptNames()`），动态反映系统已装字体。不硬编码存在性。若系统未装 HelveticaNeue，该面自动剔除，fallback 退化为保留原 face（安全降级）。

### 2.2 script == .latin 判定可靠性 ✅

```swift
// FontCatalogBuilder.swift:45-54
public static func script(for text: String) → ScriptKind {
    for scalar in text.unicodeScalars {
        if (0x4E00...0x9FFF).contains(scalar.value) ||
           (0x3400...0x4DBF).contains(scalar.value) ||
           (0x3040...0x30FF).contains(scalar.value) { return .cjk }
    }
    return .latin
}
```

- `-¥5.94`: `U+002D(-)`, `U+00A5(¥)`, `U+35(5)`, `U+2E(.)`, `U+39(9)`, `U+34(4)` → 均不在 CJK 区间 → `.latin` ✅
- `账单详情`: `U+8D26`, `U+5355`, `U+8BE6`, `U+60C5` → 均在 0x4E00-0x9FFF → `.cjk` ✅
- ¥ 符号（U+00A5）和数字/小数点/负号/美元均不误判为 CJK ✅

### 2.3 exact 条件严谨性 ✅

```swift
// StyleAnalyzer.swift:72
if case .exact = match { return face }
```

Swift 模式匹配 `if case .exact = match` 精确匹配 `.exact(Double)`，不捕获 `.approximate` 或 `.unmatched`。这意味着：
- `.exact(score)` → 不动 ✅
- `.approximate(score, face)` → 进入回退 ✅
- `.unmatched(face)` → 进入回退 ✅

### 2.4 回退仅改 font，其余属性保留 ✅

// StyleAnalyzer.swift:80-81

**结论**: font 变更隔离正确，颜色/背景/tracking/baseline 均不被字体替换影响。

## 4. 最可能漏测的场景

### P0 — 混合 CJK+拉丁文本（高风险，当前无覆盖）

**场景**: `"¥100元"` 或 `"总计 ¥1,234.56"`

- `script(for:)` 遇到 `元`(U+5143) → 返回 `.cjk` → **整个块跳过回退**
- 但该块以拉丁数字为主体，Thonburi 回退不触发
- **用户影响**: 金融截图中"¥xxx元"混合块可能仍用 Thonburi 渲染数字

**根因**: `script(for:)` 是 block 级判定，一个 CJK 字就判定整个块为 CJK。对混合文本不够精细。

**建议**: 增加测试 `"¥100元"` 验证当前行为是否可接受（可能"可接受"——混合块可视为 CJK 块）。若不可接受，需升级为 character-level 或 dominant-script 判定。

### P1 — 空 catalog / 白名单面全部缺失（安全降级但未测试）

**场景**: 系统未装任何白名单字体（极端但可能，如最小化 macOS 安装）

- `available` 为空 → `guard let best` 失败 → 返回原 face（Thonburi）
- 回退静默失效，无 warning
- **未测试**: 无 test 覆盖 `available.isEmpty` 分支

**建议**: 补充一个测试，构造不含任何白名单面的 catalog，验证返回原 face。

### P2 — ambiguous 边界（exact 判定在 ambiguous 场景下的行为）

**场景**: FontMatcher 返回 `.exact(score)` 但 `ambiguous=true`

- `if case .exact = match` → 不动（exact + ambiguous 仍跳过回退）
- 这是正确的（exact 就是 exact），但无测试覆盖
- **影响**: 低（模糊 exact 仍可信，不应被替换）

### P3 — displayName 使用 PS 名（非人类可读）

**场景**: StyleAnalyzer.swift:81 — `displayName: best.postScriptName`

- 回退后面 displayName = "HelveticaNeue-Medium" 而非 "Helvetica Neue Medium"
- 仅影响 Inspector UI 显示，不影响渲染
- **影响**: 极低（cosmetic）

### P4 — 字重跳变

**场景**: Thonburi (weight=200) 回退到 HelveticaNeue-Medium (weight=500) 或 Avenir-Medium (weight=500)

- 字重从 200 跳到 500，视觉上笔画变粗
- 白名单按字重"最近"选择，但原面 200 与最近白名单面 400 差 200
- **用户可能感知**: 数字笔画比原图略粗

**建议**: 若用户反馈字重差异，可考虑在白名单增加 HelveticaNeue-Light (300) 缩小字重差距。
